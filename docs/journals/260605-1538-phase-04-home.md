## The Brutal Truth

The asset extraction pipeline for this Figma file is fundamentally broken. `get_figma_image` returns HTTP 500; `get_media_file` returns 401. So we can't automate asset downloads — the UI builder had to request manual exports from the user three times across iterations. This is infuriating because we sold the two-track parallel protocol on the idea that UI could run independently, but every asset blocker yanked the orbit. The countdown LCD font required bundling a third-party font file (DSEG7 Classic), which added friction and isn't scalable if every screen has custom typography. And the reviewer caught that we shipped Phase 03 with a systemic bug: the shared header was missing `statusBarsPadding()` under edge-to-edge — status bar overlapped the logo, now fixed, but that's a lesson in "don't defer shared component polish".

## Technical Details

**Asset Extraction (the pain point)**:
- `get_figma_image` (per-node render): HTTP 500 consistently
- `get_media_file` (S3 pull): 401 Unauthorized
- `get_design_item_image` (view-only, no bytes): Cannot save

**Countdown LCD Font**:

- `HomeViewModel.CountdownText` now uses `DSeg7 Classic` + TextStyle override

**Edge-to-Edge Insets (H-01 catch)**:

## What We Tried

1. **Parallel Track A (UI) + Track B (ViewModel)**: Worked well structurally, but asset blocks serialized the UI agent's work.
2. **LCD font via Monospace fallback**: Failed; user saw proportional digits. Switched to DSEG7 Classic download + bundle.
3. **Ghost "8" layer for LCD effect**: Added TextStyle with low alpha underneath real digits — gives that classic seven-segment unlit-segment faint look.
4. **Visual verification**: Flipped `startDestination` to HOME, took emulator screenshots via `adb`, caught inset bug concretely before user reported it.

## Root Cause Analysis

1. **Asset extraction pipeline**: This Figma file's MoMorph APIs are unreliable (HTTP 500, 401). Per-node render is not viable. Fallback to manual user exports is the only reliable path *for this file*.
2. **Countdown font choice in spec**: Design chose a decorative seven-segment font without flagging that Android Material 3 doesn't ship with it. Assumption was we'd have Monospace — wrong. Next time, ask in clarifications: "Is this font bundled or fallback to system?"
3. **Shared component polish deferred**: Phase 03 didn't verify window insets in the shared header because it shipped quickly. Phase 04 exposed the bug. Lesson: test shared components *in isolation* before other screens reuse them.

## Lessons Learned

1. **Asset extraction is not a solved problem.** For this Figma file, treat automated export as unreliable. Plan for user-provided Figma exports; verify each with the Read tool before wiring.
2. **Custom typography demands planning.** LCD/digital fonts need the actual font file (not a system fallback) *and* require bundling. Add to clarifications upfront: "Which fonts are custom? We need to bundle them."
3. **Shared components must be complete before reuse.** Don't ship a shared header without testing insets, padding, and accessibility in a real screen context. Phase 03 cut a corner; Phase 04 paid for it.
4. **Visual verification is non-negotiable.** Screenshots catch bugs that static code review misses (especially layout, insets, typography).
